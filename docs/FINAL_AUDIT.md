## Security and quality sweep

- SQL statements handling request values use positional parameters. The few dynamic SQL identifiers in `lib/outbox-core.mjs` come from fixed internal maps, and incident sort/filter choices are allowlisted. Cypher values use parameters; labels in the worker come from a fixed list.
- `test-results/security-scan.txt` records 0 legacy credential strings and 0 template/meta strings. `.env` is ignored and excluded from ZIP. `lib/db.ts` requires all database environment variables. `lib/auth.ts` sets HttpOnly, SameSite and production Secure cookie flags.
- All 13 Route Handler files were inspected for access controls. Public: `GET/POST /api/auth`; signed-in: `DELETE /api/auth`, `GET/POST /api/incidents`, `PATCH /api/incidents/[id]`, `GET /api/incidents/[id]/events`, `GET /api/incidents/[id]/insights`, `GET /api/similar`, `GET /api/insights`, `GET /api/services/[id]/blast-radius`; admin: `DELETE /api/incidents/[id]`, `POST /api/incidents/[id]/reopen`, all `/api/admin`, `/api/admin/graph-sync`, `/api/admin/users`, `/api/admin/users/[id]` methods. `ENDPOINT_UI.md` maps each to the UI.
- UI sign-out promise now handles failures. Graph sync schedules a caught background promise. No sensitive `console.log` was found in application routes/libraries; setup prints generated demo credentials intentionally once to the operator.
- `npm ls --depth=0` completed. Two extraneous optional packages appeared in local `node_modules`; no declared unused dependency was confirmed. No dead application route was established by this inspection.
- The scan found files over 300 lines: `scripts/seed-bulk.mjs` (369), `app/style.css` (505), generated `db/schema.snapshot.sql` (630), generated `package-lock.json` (1341). They are formatted, not minified. Application TypeScript component/route files remain below the requested ~250-line target.
- `npm audit --omit=dev --json` produced `test-results/npm-audit.json`: 0 production advisories after overriding Next 15's transitive PostCSS to patched 8.5.31. `npm ls postcss --all` confirms the resolved version. This changes no application library or required framework major version.

## Advanced features used by the application

SQL: (1) transactional writes with audit actor context and graph outbox; (2) triggers for audit/integrity/outbox; (3) stored `resolve_incident`/`reopen_incident` functions called by routes; (4) views for dashboard aggregation; (5) full-text search with generated vector and GIN index, queried by incident filters; (6) indexed joins/aggregates for incidents and symptoms. Neo4j: variable-length dependency traversal, root-cause and symptom relationships, and similarity explanations, used by graph endpoints and the UI. The existence of an index does not prove the planner chose it on 180 rows; see F5.

## Red flags remaining, by severity

1. **Medium:** Real Git/GitHub history and two-member contributions do not exist in this deliverable; requirement 14 remains human work. The team identities are recorded, but authorship is not inferred from them.
2. **Medium:** Final UI at 380px, accessibility behavior and authentic screenshots have not been checked by a human browser session.
3. **Medium:** Graph resync removes project-labeled graph data; use a dedicated Neo4j instance and confirm the target URI before running it.
4. **Low:** `scripts/test-db.mjs` now refuses to replace a pre-existing `_test` database; if a stale test database remains after an interrupted run, its owner must inspect and remove it manually.
5. **Low:** The graph is justified by connected failure data and query shape, not by measured speed here. The natural FTS plan does not use GIN at this data size. A larger, representative workload is needed for performance claims.
